# PRD —— 漫剧生产系统产品需求

> 本文档定义必须实现的功能与业务规则（P1）。技术约束见 ARCHITECTURE.md，接口字段见 API.md。优先级：P0=MVP 必须，P1=首版必须，P2=后续增强。

## 1. 产品定位

面向个人创作者与小团队的自托管漫剧生产工作台，以本地 ComfyUI 为渲染底座、ComfyKit 格式工作流为可插拔能力单元，把剧本逐步转化为角色资产、分镜、视频片段与成片。

| 核心价值 | 落地规则 |
| --- | --- |
| 成本可控 | 图像、TTS 与音视频链路全部走本地 ComfyUI；H3 视频用本地权重原生节点（D-10），免云端按秒计费，参考图与提示词不出境 |
| 工作流自由 | 换模型只换 workflow JSON，不改代码 |
| 一致性可控 | 资产四层锚定 + 自动一致性度量（见 CONSISTENCY.md） |
| 生产可回溯 | 资产版本化、任务持久化、失败可续跑，任何一步可单独重做 |

## 2. 非目标（本期不做）

- 不做公网多租户 SaaS 与计费体系
- 不做模型训练与微调
- 不做专业视频剪辑器（成片可导出至剪映继续加工）
- 不实现 ComfyUI 本体，仅作为外部服务消费
- 不做众包协作与实时多人编辑

## 3. 已确认产品决策（P0，不得推翻）

| 决策项 | 确认结果 | 落地规则 |
| --- | --- | --- |
| 合成与导出 | 分开，导出为独立阶段 | compose 生成可预览 composition；export 以 composition_id 创建独立任务与导出记录 |
| 音画时长冲突 | 配音时长为准，超出容差转审核 | 容差内自动补帧/截断；超容差置 `review` 并阻塞合成，审核或重生成后继续 |
| 音频来源 | 优先 H3 VA 同次生成音频；TTS 仅补救 | 仅音频缺失/无效、对白检查失败或人工审核不通过时才创建 TTS 任务；BGM/SFX 可选 |
| 道具锚定图 | 关键道具可选生成 | 普通道具依赖文字描述；仅显式 `anchor_required=true` 才作为硬依赖 |
| H3 生成通道 | 本地权重原生节点（UNETLoader + MiniMaxH3ReferenceToVideo / MiniMaxH3ImageToVideo，D-10） | 参考图与提示词不出境、免云端计费与 Comfy 账号依赖；需 ≥24GB 显存实例（验证目标 A10，V100 未验证）与 5 项本地权重部署；云端 Partner Node 已弃用 |

## 4. 术语

| 术语 | 定义 |
| --- | --- |
| 项目 | 一部作品的顶层容器，包含剧本、场景、镜头与资产 |
| 场景 | 故事发生的空间单元，一个场景包含若干镜头 |
| 镜头 | 最小的生成单元，对应一张分镜图与一段视频 |
| 资产 | 可复用的视觉或听觉素材，含角色、场景、道具、分镜图、视频、音频 |
| 工作流 | ComfyUI 的工作流 JSON，符合 ComfyKit 标记规范 |
| 绑定 | 语义参数名与工作流节点字段之间的映射关系 |
| 任务 | 一次工作流执行请求，有独立生命周期与结果 |
| 锚定图 | 用于约束后续镜头一致性的基准资产 |

## 5. 用户与典型场景

| 角色 | 核心诉求 |
| --- | --- |
| 创作者（主要使用者） | 快速产出、结果可控、改起来方便 |
| 运维者 | 部署简单、故障可定位、资源可控 |

典型场景：A 小说改编全流程；B 已有剧本直接分镜；C 角色跑偏仅重跑问题镜头；D 更换模型仅重新生成分镜图。

用户旅程：创建项目 → 输入剧本 → 解析审核 → 生成并锁定角色资产 → 拆解分镜 → 逐镜生成图 → H3 VA 生成音视频 → 检查视频/对白/音频（必要时 TTS 补救）→ 合成预览 → 独立导出。每个环节均支持暂停、审核、单点重做与回滚。

## 6. 功能模块

### 6.1 M1 项目管理

| 编号 | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| M1-01 | 创建项目，填写名称、类型、画幅比 | P0 | 创建后进入草稿态，列表可见 |
| M1-02 | 项目列表，按状态筛选与关键字搜索 | P0 | 20 条以内首屏加载小于 1 秒 |
| M1-03 | 项目详情展示当前进度与下一步操作 | P0 | 状态与实际数据一致 |
| M1-04 | 项目设置：画幅、默认工作流、模型偏好 | P1 | 修改后对后续任务生效，不影响已生成结果 |
| M1-05 | 项目归档与删除 | P1 | 删除需二次确认，资产同步清理 |
| M1-06 | 项目复制（含资产，不含任务） | P2 | 复制后可独立编辑 |

边界与异常：同名项目允许存在。删除采用软删除；删除进行中的项目需先取消或对账其下任务；被任务引用的文件不得立即物理清理，进入延迟清理队列，恢复期内可撤销删除。

### 6.2 M2 剧本与分镜

| 编号 | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| M2-01 | 粘贴或上传剧本文本 | P0 | 支持纯文本与 Markdown，单次上限 5 万字符 |
| M2-02 | 调用语言模型解析出场景、角色、镜头草案 | P0 | 输出结构化 JSON，字段完整可校验 |
| M2-03 | 解析结果人工审核与编辑 | P0 | 场景与镜头均可增删改，改动即时保存 |
| M2-04 | 镜头卡片显示编号、台词摘要、时长预估、状态角标 | P0 | 角标与任务状态联动 |
| M2-05 | 场景内镜头拖拽排序 | P1 | 仅允许同场景内排序，跨场景拖动被禁止 |
| M2-06 | 场景与镜头批量删除 | P1 | 删除前提示关联资产数量 |
| M2-07 | 分镜导出为结构化文件 | P2 | 导出内容可再次导入还原 |
| M2-08 | 剧本体量评估 | P0 | 解析前先算出可制作集数、总时长估算、每集预估分镜数，不产出分镜 |
| M2-09 | 制作范围选择 | P0 | 用户从评估结果中选定集数范围，未选中的集不解析、不占生成资源 |
| M2-10 | 剧本超量提示 | P0 | 估算集数超过单次制作建议上限时，提示剧本过长、建议裁剪或分批制作 |

业务规则（P1，全部强制）：
- 每次保存/提交剧本形成不可变 `script_version`，记录内容快照、内容哈希、创建时间；评估与解析必须引用明确版本，不得静默读取最新剧本
- 评估结果记录评估算法/提示词版本、预计时长区间、预计集数及估算假设；估算需区分对白、旁白、动作/纯视觉和转场时长，允许用户调整
- 解析必须使用用户确认的 `script_version` 与集数范围；剧本版本变化后需重新评估或明确选择沿用旧版本
- 解析先生成候选解析版本，展示新增/删除/修改的场景与镜头及受影响任务/资产；用户确认后才原子切换为当前版本
- 未确认候选解析不得覆盖当前分镜、人工编辑、已确认产物或合成记录；旧版本保留追溯，关联运行任务需取消或标记过期
- 场景编号与镜头编号在项目内唯一，删除后不重排，保留空号
- 未解析出镜头的场景不允许进入生成阶段
- 镜头排序变更后，仅后续未生成的镜头受影响
- 解析必须以已完成集数评估为前提，未评估不允许直接调用解析
- 单次解析仅产出用户选定范围内的集，超出范围的剧本内容不落库
- 制作范围为逐集制作时，可在后续按集追加解析，已解析的集不重复生成
- 场景追加出场集数不受解析范围限制，但超出已解析范围的集不会自动产出镜头；该集须先执行追加解析、产出分镜后方可进入生成阶段（接口返回中带 `requires_parse` 提示，见 API.md 场景接口）
- 解析完成后页面展示结果摘要卡片（场景/角色/道具数量），唯一出口为『去资产库 →』（D-21 流转链）；生图入口不在剧本阶段页面

### 6.3 M3 资产库

| 编号 | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| M3-01 | 资产分类：角色、场景、道具（资产库仅承载项目级公共资产）；分镜图、分镜视频、末帧为集级资产，在独立的分镜图环节与分镜看板生成 | P0 | 分类可筛选；资产库不再出现分镜图/分镜视频分类 |
| M3-02 | 资产上传与生成入库 | P0 | 记录来源（上传或任务） |
| M3-03 | 资产版本管理，可查看历史版本 | P0 | 旧版本可回滚为当前版本 |
| M3-04 | 资产锁定，锁定后不可删除、不可被覆盖 | P1 | 锁定资产作为锚定图使用；分镜图锁定后禁止重新生成或替换，单镜、场景级批量、跨场景批量三条出图通道均返回 409 asset_locked，需先解锁 |
| M3-05 | 资产引用计数，显示被多少镜头引用 | P1 | 删除前展示引用数量 |
| M3-06 | 全局资产选择器 | P1 | 可从任意镜头卡片唤起 |
| M3-07 | 缩略图自动生成 | P0 | 长边 256px，列表使用缩略图 |
| M3-08 | 资产批量导出 | P2 | 按分类打包下载 |

业务规则：
- 资产分层（D-21）：解析产出的角色定妆图、场景基准图、道具锚定图为**项目级公共资产**，跨集复用，统一在资产库『制作资产区』生成（card 含实体名称绑定标签与生图提示词）；分镜图/分镜视频/末帧为**集级资产**，按集归属，在**独立的分镜图环节**生成分镜图、在分镜看板生成视频，不进入公共资产生图流程
- 人工审核闸口（D-23）：流程改为 剧本 → 解析 → 资产库 → **资产人工审核** → **分镜图（独立菜单，挂在资产库节点下）** → **分镜图人工确认** → 分镜看板 → 视频合成。资产库公共资产图生成完毕后须人工审核，通过才放行分镜图生成；不满意的资产可修改或替换后重新提交审核。分镜图逐镜出图后须人工确认，全部确认后方可进入分镜看板生成视频
- 制作资产区图片按实体名称绑定（asset 关联 character/scene/prop），供提示词 @名称 引用解析与生成槽位注入（角色→ref_identity、场景→ref_scene、道具→ref_prop，见 D-16/D-20 与 WORKFLOW.md 六槽位）
- 资产定义（AssetPlan，2026-10-28）：解析落库后一次性定稿五类定义（角色/场景/道具/分镜图/分镜视频）的名称、占位路径、提示词与参考依赖；名称与路径一经生成永不修改，提示词随重新解析刷新。资产库批量制作、分镜图批量生成、分镜看板批量出视频均按定义触发，无匹配定义时回退镜头级/项目级通道；参考图槽位由定义绑定决定并按工作流能力声明过滤，绑定快照随任务持久化（重试不换版本）
- 齐全度门禁：公共资产（角色/场景/道具参考图）全部生成后才可提交人工审核；审核通过后才可生成分镜图（未齐全时『审核通过』禁用；未通过审核时三条分镜图生成通道均返回 409）
- 被引用的资产删除时，需提示并解绑或替换；删除默认软删除，物理清理延迟执行
- 锚定图（角色定妆图、场景基准图）必须锁定后才能参与要求一致性的生成模式
- 资产文件名使用唯一 ID，不使用原始文件名
- 引用关系表为资产依赖的权威来源，`ref_count` 仅用于展示/加速，不作为唯一删除依据
- 回滚不得改写历史版本内容，应切换当前版本指针或创建新的当前版本记录；被任务引用的资产在任务结束前不得物理删除

### 6.4 M4 生成引擎

| 编号 | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| M4-01 | 文生图：按提示词与尺寸生成分镜图 | P0 | 产物落盘，可预览 |
| M4-02 | H3 VA 图生音视频：以分镜图及角色/场景参考生成带音频的视频 | P0 | 产物可播放；按工作流能力声明检查视频与音频轨；记录实际视频/音频时长、对白检查结果与来源；视频时长符合所选 H3 工作流时长规则（API 节点 4–15 整数秒，见 WORKFLOW.md） |
| M4-03 | 参考图约束：把角色与场景锚定图作为参考图传入 | P0 | 参考图正确上传并注入节点 |
| M4-04 | TTS 配音补救：仅在 H3 VA 音频缺失、无效或对白审核不通过时按需生成 | P1 | 支持指定音色，可试听；补救任务显式标记原因，不覆盖原始 H3 音视频产物，可单独重做 |
| M4-05 | 生成通道可切换（本地 ComfyUI / 三方 API） | P0 | 未配置 ComfyUI 时自动降级 |
| M4-06 | 单镜重做与整场景重做 | P0 | 重做不影响其他已完成镜头 |
| M4-07 | 生成前预估显存与耗时提示 | P2 | 依据历史任务统计 |

业务规则：
- 默认视频工作流为 H3 VA（标准实现见 WORKFLOW.md，官方 MiniMax H3 Partner Node，云端计费）；H3 VA 一次调用尽可能同时产出视频与其对应音频，不得默认再为每个对白镜头无条件创建 TTS 任务
- H3 VA 音频能力必须通过工作流 `capabilities` 明确声明；音频封装在 MP4 内时用媒体探测工具检测音轨并按需提取，不强制要求工作流额外输出独立音频文件
- H3 VA 生成后必须执行媒体探测与对白检查；TTS 只作为音频缺失/无效、对白未生成/不可辨识或用户审核不通过时的补救路径
- 所有生成通过统一能力接口调用，业务层不出现 ComfyUI 专有参数
- 生成结果自动入库为资产，并记录来源任务与完整输入版本快照
- 尺寸按工作流绑定能力自动对齐，无法改写时需明确提示
- 统一生成模式：`text_only`、`image_to_video`、`reference_guided`；单镜、批量和重做复用同一套输入解析器
- 生成确认界面展示实际将注入的角色/场景/道具参考图、首帧、尾帧、前镜尾帧、工作流版本与关键参数
- 一致性模式下必需的参考图缺失或工作流不支持时必须阻断或要求用户显式确认降级，不得静默降级

### 6.5 M5 工作流管理

| 编号 | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| M5-01 | 上传 workflow JSON | P0 | 上限 10MB，带上传进度 |
| M5-02 | 格式校验：仅接受 API 格式 | P0 | 画布格式直接拒绝并说明原因 |
| M5-03 | 标记解析：扫描节点标题中的参数标记 | P0 | 解析出参数名、字段、是否必填、是否媒体 |
| M5-04 | 输出标记解析 | P0 | 列出所有输出变量名 |
| M5-05 | 解析结果可视化预览 | P0 | 表格展示绑定关系 |
| M5-06 | 设为默认工作流（按类型） | P1 | 同类型同时只有一个默认 |
| M5-07 | 工作流版本管理 | P1 | 每个任务记录所用版本 |
| M5-08 | 连通性测试（不实际生成） | P0 | 仅校验可达性与标记完整性 |
| M5-09 | 工作流删除保护 | P1 | 被默认引用或任务引用时禁止删除 |

校验规则：
- 顶层必须是节点 ID 到节点对象的映射，每个节点含 class_type 与 inputs
- P0 工作流必须存在明确的 `$output.*` 输出标记，否则拒绝保存
- 必填参数逐项按参数名、类型、节点类型、绑定可用性校验，不得以匹配总数替代
- 保存/修改工作流均生成不可变版本；运行任务固定引用启动时的版本
- 校验错误定位到节点 ID、字段名，并区分阻断错误与非阻断警告

### 6.7 M7 合成与导出

| M7-01 | 按镜头顺序合成视频 | P0 | 输出可预览 MP4；有配音镜头以实际配音时长为准，无配音镜头按 duration；超容差镜头须审核放行 |

| M7-03 | 字幕烧制或外挂 | P1 | 支持两种模式 |
| M7-04 | 背景音乐混音与音量控制 | P1 | 人声优先，BGM 可降噪 |
| M7-05 | 导出剪映草稿 | P2 | 结构可被剪映识别 |
| M7-06 | 单集导出与整部导出 | P1 | 合成与导出分离；导出任务独立创建、可查询、可重试；单集/整部导出范围明确 |

#### 时间轴计算（P0，研发必须严格遵守，不得各写一套）

时间轴基准：有对白/旁白音频的镜头以 `shot.actual_duration`（优先 H3 VA 实际音频时长；TTS 补救后为补救音频时长）为成片时长基准；无配音的纯视觉/转场镜头以 `shot.duration` 为基准。`shot.duration` 仅是生成视频的参考输入，不覆盖已有配音的实际时长。

| 情形 | 时间轴取值 |
| --- | --- |
| H3 VA 内嵌音频或 TTS 补救音频有效 | 取 `shot.actual_duration` |
| 按 `shot_kind` 允许无配音且未生成配音 | 取 `shot.duration` |
| 按策略要求配音但音频缺失/失效 | 合成前校验拒绝，不得回退到预估时长 |
| 镜头视频缺失/失效 | 合成前校验拒绝 |

镜头起始时间 = 前面所有镜头时长之和，逐镜累加，不做四舍五入，最终仅在写 SRT 时间码时按毫秒取整。

#### 音画不等长处理与审核闸口

`compose_tolerance` 默认 0.5 秒，允许范围 0–2 秒。以音频实际时长为目标时长基准（无配音镜头以 `shot.duration` 为目标）。

| 视频与目标时长差值 | 处理方式 | 是否阻塞合成 |
| --- | --- | --- |
| 差值不超过容差 | 视频短则末帧定格补齐；视频长则截断尾部 | 否，记录对齐方式 |
| 差值超过容差 | 将镜头置为 `review`，记录 `duration_mismatch`、视频时长、目标时长和差值；允许重生成视频或人工确认后放行 | 是，未审核通过不得合成 |

人工确认放行必须写入审核人、时间、处理方式和差值快照。若随后重生成视频、重新生成配音或修改 `duration`，该审核自动失效并重新校验。不得仅把超容差差异写入 warning 后继续默认交付。

#### 字幕规则

字幕文本来自 `shot.dialogue`，按镜头归属，不跨镜头合并。时间优先使用 H3 VA 对白时间戳或 TTS 补救音频词/句级时间戳，其次句级对齐；无时间戳时才按文本长度估算，并在合成报告中标注为估算时间。多人对白必须关联对应 `dialogue_segments`，不得将所有角色台词误认为同一说话人。

| 规则 | 说明 |
| --- | --- |
| 文本来源 | shot.dialogue，为空时该镜头不生成字幕条目 |
| 时间范围 | 该镜头在成片中的起止时间 |
| 单句超长切分 | dialogue 超过 40 字时按标点切分为多条，切分后时间按字符数比例分配 |
| 最短显示时长 | 1 秒为软约束；字幕不得越过所属镜头/对白段边界；冲突时优先按时间戳调整、合并/拆分字幕或提示人工处理，不得顺延覆盖下一镜头 |
| 编码格式 | sidecar 模式输出 UTF-8 的 SRT 文件，与成片同目录、同名、扩展名 srt |

字幕模式：`burn`（烧入画面，ffmpeg subtitles 滤镜，字体样式取 FRONTEND.md 视觉规范）/ `sidecar`（仅输出 SRT，画面不烧字幕）。`include_subtitle=false` 时两种模式均不执行。

#### BGM 混音

BGM 按 `bgm.volume` 与人声混音，人声优先。BGM 短于成片总时长时循环，长于总时长时在结尾 1 秒内淡出。混音完成后做响度归一，整体响度目标 -16 LUFS，峰值不超过 -1 dBTP。

#### 镜头类型与音频必需性

「音频必需」指必须存在通过检查的有效对白/旁白音频，不等于必须调用 TTS。优先采用 H3 VA 同次生成的音轨；仅在音频缺失、无效、对白检查失败或人工审核不通过时调用 TTS 补救。

| shot_kind | 有效音频策略 | 视频策略 | 字幕策略 |
| --- | --- | --- | --- |
| dialogue | 必需；优先 H3 VA 音轨，必要时 TTS 补救；多人对白每段必须有有效 `speaker_id` 或经审核确认的默认音色 | 必需 | 有台词时生成 |
| narration | 必需；优先 H3 VA 音轨，必要时按旁白音色配置 TTS 补救，不依赖 `shot.character_id` | 必需 | 有旁白文本时生成 |
| visual | 默认可选；若存在非空对白/旁白文本则必须由人工明确改为对应类型或确认无配音 | 必需 | 无文本不生成 |
| transition | 默认可选；若有对白则按 dialogue 策略校验 | 必需 | 有文本时生成 |

BGM/SFX 均为可选轨道，可由独立工作流生成或从素材库选择；缺少 BGM/SFX 不阻塞合成。所有音频轨道须经 `timeline_tracks` 表达其来源、作用域、时间范围与音量。

#### 合成前校验（任一不满足直接返回 422，不进入任务队列）

1. 项目状态为 active
2. 全部参与合成的镜头均已生成视频
3. 按 `shot_kind` 校验必需产物：对白/旁白镜头需满足对应音频策略；纯视觉镜头允许无配音但必须有视频；转场镜头按配置校验
4. 有配音的镜头以音频实际时长为排轴依据；无配音镜头使用 `duration`，合成报告记录时长来源
5. 启用字幕时，各镜头 dialogue 与镜头归属关系完整，字幕时间不得越过镜头边界
