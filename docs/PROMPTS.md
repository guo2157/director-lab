# PROMPTS —— 剧本解析与提示词规范

> 本文档定义独立语言模型适配层的两项能力规范与全部提示词模板（P1）。剧本解析与分镜设计均由语言模型完成，不经过 ComfyUI 渲染，与 WORKFLOW.md 的工作流体系相互独立。字段名与类型口径以 API.md / DATABASE.md 为准，业务规则与必填校验以本文档为准。

## 1. 适用范围

- 剧本解析：由 `POST /api/projects/{id}/parse` 触发，使用系统设置中的语言模型配置（模型、base_url、密钥），不经过 ComfyUI 工作流
- 分镜设计：与解析同次完成，输出结构化分镜表
- 生成分镜图/视频提示词的结构化模板：供用户与系统拼装使用，对应 `shot.image_prompt` 与 `shot.video_prompt`

## 2. 剧本解析提示词模板

独立语言模型适配层使用以下系统提示词模板进行剧本解析。该提示词定义了 AI 编剧的角色、创作规则和输出格式，确保解析结果结构化且可直接用于后续资产生成和分镜拆解。

**提示词核心要点**

| 模块 | 内容 |
| --- | --- |
| 身份定义 | 专业短剧编剧、商业故事策划和影视剧本顾问 |
| 项目信息 | 剧名、题材类型、核心受众、播出形式、总集数、单集时长、整体风格、制作预算与场景限制、参考作品 |
| 核心创意 | 一句话故事（主角/目标/阻碍/代价/卖点）、故事简介、核心主题、主要看点、创新点 |
| 人物设定 | 姓名、年龄、身份、外在形象、核心欲望、真实动机、性格特点、最大弱点、秘密和恐惧、人物关系、人物变化、关键选择原因 |
| 故事结构 | 开篇核心事件、主角目标与困境、持续升级的核心冲突、关键人物关系变化、中段重要转折、主角付出代价后的选择、高潮、最终对决和结局 |
| 单集规则 | 开场钩子、事件推进、冲突升级、阶段性结果、结尾钩子 |
| 情绪设计 | 爽点、虐点、甜点、危机和反转，每个情绪爆发必须有事件和人物动机支撑 |
| 反转与伏笔 | 所有重要反转提前埋设线索，建立伏笔清单（出现集数/观众判断/真相揭晓集数/回收方式） |
| 质量控制 | 人物行为一致性、时间线一致性、冲突因果链、反转合理性、台词自然度、每集信息增量、场景可拍摄性、结局回应开篇 |
| 创作原则 | 前 3 集抓人能力、冲突升级机制、情绪兑现、悬念与信息差控制、成本与场景控制 |
| 动作节拍 | 复合动作、道具交接、两人以上肢体互动、伴随显著位移的动作，拆成可独立拍摄的节拍；单镜最多 3 个节拍，单节拍不超过 2 秒，超出拆镜头 |
| 情绪曲线 | 每个镜头给出起点情绪、触发事件、转折所在秒数、终点情绪与外化表现；不得只标一个情绪词 |
| 单集节奏 | 每集须保住开场钩子、冲突升级、情绪释放、结尾悬念四个节拍，不得按固定字数或固定镜头数截断；同时产出本集目标、节奏曲线、悬念类型与下一集承接点 |
| 可校验输出 | 角色、场景、道具、镜头一律使用稳定 ID；每镜给出参考资产、生成方式、时长、对白、音效与审核条件；只输出可校验 JSON，不输出自然语言分析报告 |

**工作流程**：解析为一次性调用，系统将完整提示词和用户输入的剧本文本一并发送给语言模型。返回的 JSON 由前端渲染为分镜审核页，用户可人工编辑、增删场景和镜头后再确认进入生成阶段。

## 3. 解析输出 JSON 结构与归一化规则（P0 强约束）

解析结果按以下结构输出 JSON：

- `project_analysis`：含 `summary`（核心创意与故事卖点）、`theme`（核心主题）、`highlights`（主要看点）、`foreshadowing`（伏笔清单数组，每项含 `setup_episode`、`audience_guess`、`reveal_episode`、`payoff`）
- `characters`：主要人物档案及人物关系图，每项含 `name`、`description`、`traits`、`appearance`。解析不产出 `voice_id`，由用户在审核阶段补充
- `props`：道具数组，每项含 `name`（项目内唯一，用于 @名称 引用）、`description`、`appearance`
- `scenes`：每个场景含 `episode`、`title`、`description`、`time_note`（可为空）、`shots` 数组
- `shots`：每个镜头含 `episode`、`seq`（同场景同集内唯一）、`scene_id`、`character_id`（主说话角色，可空）、`props`（道具名数组）、`dialogue`、`dialogue_segments`（每项含 `speaker_id`、兼容字段 `speaker`、`text`、`emotion`、`order`，可选 `start_time/end_time`；单说话人可为空）、`speaker`（可空）、`emotion`（neutral/happy/sad/angry/fearful，取情绪曲线终点）、`emotion_curve`（from/trigger/turn_at/to/expression）、`beats`（上限 3 个，每项含 action/start_pose/end_pose/duration）、`start_state`（六项枚举，取值域见 DATABASE.md）、`end_state`（六项枚举）、`image_prompt`、`video_prompt`（可为空，为空时由系统按结构化模板拼装）、`shot_type`、`camera_angle`、`camera_movement`、`transition`、`shot_purpose`、`duration`、`shot_kind`（dialogue/narration/visual/transition）、`time_jump`（默认 false）、`requires_prev_frame`（默认 false）
- `episodes`：分集规划数组，每项含 `episode`、`goal`、`rhythm_curve`、`cliffhanger_type`（信息缺失/危机逼近/反转揭示/关系破裂）、`hook_to_next`、`locked`（默认 false）。整体写入 `project.episode_plan`，按集覆盖未锁定集

字段口径以 API.md 为准，两处保持一致。

### 3.1 归一化规则（强约束）

- 每个 shot 必须输出 `shot_kind`、`duration`、`time_jump`、`requires_prev_frame`；兼容旧解析结果时，由服务端适配层按规则补齐：有 `dialogue` 默认 `dialogue`，无 `dialogue` 默认 `visual`；`time_jump=false`、`requires_prev_frame=false`。补齐必须写入 `parse_warnings`，不能静默当作模型原始输出
- `dialogue_segments[].speaker_id` 是唯一权威说话人标识。解析模型可以同时输出 `speaker` 名称，但落库前必须按项目角色名称映射到 `speaker_id`；映射失败时保留原始名称、产生审核问题，禁止直接使用 `shot.character_id` 覆盖分段说话人
- `shot.character_id` 只作为镜头主角色/视觉参考，不作为多人对白音色选择依据。单人台词若未提供 `dialogue_segments`，适配层可根据明确的 `speaker_id` 或 `speaker` 创建单段结构；仍无法映射则需人工确认
- 解析阶段必须产出 `emotion`，用于 H3 VA 的对白/声音提示词以及必要时的 TTS 补救情感控制；缺失时该镜头 emotion 落为 `neutral`，不报错但记入解析警告

### 3.2 审核准入条件

解析结果必须经人工确认才能进入生成阶段。确认前界面需校验以下四项，未通过时给出明确提示但仍允许用户强制确认：

| 条件 | 判定方式 | 不满足的后果 |
| --- | --- | --- |
| 角色与场景实体信息完整 | characters 与 scenes 数组均非空，且每个角色有 name、description、appearance 等必填字段，每个场景有 title、description | 无法生成定妆图与基准图，一致性锚定缺失 |
| 镜头数与剧本体量匹配 | 镜头总数与剧本字符数、场景数呈合理比例，明显偏少时提示 | 分镜过粗，成片节奏断裂 |
| 对白均有说话人归属 | dialogue 非空的镜头，其 dialogue_segments 或 speaker 至少有一项 | 配音时无法确定音色，多人对话会串音 |
| 相邻镜头动作衔接 | 同场景同集内相邻镜头，前一镜 `end_state` 与后一镜 `start_state` 的六项枚举比对，冲突项数为 0 | 视频生成时人物姿态或道具状态跳变 |

第三条尤为关键：`shot.character_id` 是单值，只能表达『这个镜头属于哪个角色』，无法表达多人对话。多人场景必须依赖 `dialogue_segments` 中的 speaker 逐段指定音色，解析阶段就应产出该字段。

### 3.3 相邻镜头连续性校验

第四条是唯一一处程序化比对镜头数据本身的地方，也是枚举化起止状态的执行入口：

| 比对项 | 规则 |
| --- | --- |
| 比对范围 | 同场景同集内按 `seq` 相邻的镜头对，跨场景与跨集不比 |
| 比对方法 | 前镜 `end_state` 与后镜 `start_state` 逐项比对六项枚举，任一项不等即记为冲突项 |
| 不计冲突 | 任一侧为『其他』的项，记为待人工确认，不计入冲突项数 |
| 情绪与机位 | `emotion` 与 `shot.emotion` 不一致属数据错误，直接拒绝（两者同为封闭枚举）；`camera` 与 `camera_angle` 的比对仅作提示：camera_angle 为自由文本，当其恰为枚举值之一且与本项不一致时记 warning 提示人工确认，不拒绝 |

结果处理：
- 冲突项数大于 0 的镜头对，在审核界面按镜头对展示冲突详情，指明哪一项不一致
- 该项为 warning 级，允许强制确认，但生成视频时该镜头不注入 `ref_prev_frame`，避免用错的末帧引导画面
- 生成前置校验再执行一次同样比对，若此时冲突仍未解决，同样跳过末帧注入并在任务 `warnings` 中记录
- 首镜（`seq = 1`）无前序，不参与比对

## 4. 分镜设计提示词模板

独立语言模型适配层在完成剧本解析后，进入分镜设计阶段。该阶段使用以下系统提示词，将剧本转化为可执行的分镜表。

**角色定位**：专业影视导演、分镜师、摄影指导和剪辑指导，熟悉竖屏短剧的叙事节奏、演员调度、景别设计、视听语言、情绪表达和悬念剪辑。

### 4.1 工作流程（五步）

| 步骤 | 名称 | 内容 |
| --- | --- | --- |
| 1 | 剧本分析 | 分析本场戏的剧情目的、人物目标与动机、核心冲突、情绪变化与关键转折点、观众需获得的信息、重要道具与视觉线索、高潮与悬念 |
| 2 | 场景与动作拆解 | 按人物进入/观察/说话/反应/行动/冲突升级/信息揭示/情绪转折拆分场景，明确每个节点的人物位置、动作起止、台词与潜台词、观众关注主体 |
| 3 | 设计分镜 | 为每个戏剧节点决定景别、机位、构图、运镜、表演、声音、剪辑、时长，每个镜头必须说明设计意图 |
| 4 | 输出分镜表 | 按实际拍摄顺序输出结构化分镜表 |
| 5 | 剪辑与节奏检查 | 检查镜头合并/删除、听者反应、动作连续性、道具可见性、情绪画面、跳轴与视线匹配、节奏、悬念力度、拍摄可行性 |

### 4.2 分镜表输出字段

| 字段 | 说明 |
| --- | --- |
| 镜号 | 镜头序号 |
| 场次 | 所属场景 |
| 对应剧本 | 该镜头覆盖的剧本段落 |
| 景别 | 远景/全景/中景/中近景/近景/特写/大特写 |
| 机位与角度 | 平视/俯拍/仰拍/侧面/正面/过肩等 |
| 画面与人物动作 | 可拍摄的动作、表情、环境细节 |
| 运镜 | 固定/推镜/拉镜/摇镜/移镜/跟拍，说明理由 |
| 对白与声音 | 台词、环境音、音效、音乐 |
| 预计时长 | 秒数 |
| 剪辑衔接 | 切入点、反应镜头、动作匹配、悬念停顿 |
| 分镜目的 | 该镜头的叙事意图 |

### 4.3 工作规则

- 先分析剧本，再给出分镜设计依据，最后输出正式分镜表
- 剧本信息不足时，不擅自编造影响剧情的重要事件，可提出合理假设并标明
- 存在多种拍法时，优先提供最适合当前戏剧目的、制作成本和画面比例的方案
- 避免无意义的重复镜头和没有叙事作用的运镜
- 对话场景必须拍出听者的反应

### 4.4 动作节拍拆分（P0）

一个镜头里出现多个连续动作时必须拆成可独立拍摄的节拍，否则视频模型容易生成手部异常、动作跳跃、道具瞬移。

| 项 | 要求 |
| --- | --- |
| 触发条件 | 复合动作（冲过去夺走手机转身逃跑）、道具交接、两人以上肢体互动、动作伴随显著位移，必须拆 |
| 节拍构成 | 每个节拍写清动作起点、发力与执行、结果与对方反应、结束时的身体姿态，四项缺一不可 |
| 节拍粒度 | 单个节拍不超过 2 秒；超过则拆为多个镜头而非挤在一个镜头内 |
| 镜头内上限 | 单镜头最多容纳 3 个节拍，超出必须拆镜头 |
| 落库 | 写入 `shot.beats`，为节拍对象的数组，每项含 `action`、`start_pose`、`end_pose`、`duration` |
| 拆分责任 | 由语言模型在分镜设计阶段一次性拆好，不留给生成阶段处理，也不要求人工二次拆 |

超限处理：
- 单镜头节拍数超过 3 个，或单节拍时长超过 2 秒：该镜头整体判不合格并打回模型重出，不得截断节拍数组掩盖问题
- 打回时把超限原因与原始动作描述一并发给模型，重出次数上限 2 次；仍不合格则该镜头转为待人工处理，不进入后续生成
- 同一动作跨多个镜头时，节拍必须首尾相接：前一镜头末节拍 `end_pose` 等于后一镜头首节拍 `start_pose`，违反按相邻镜头连续性问题处理

拆分示例：「他冲过去夺走手机转身逃跑」拆为 4 个节拍——起步前倾伸手、抓住手机回拉、对方失稳反应、转身蹬地跑出画面。前 3 个节拍可同镜完成，第 4 个另起镜头，避免同一镜头内动作堆叠。

### 4.5 情绪变化曲线（P0）

情绪不能只标一个标签。只写「愤怒」「悲伤」无法决定何时给特写、何时给反应镜头、音乐在哪一秒转折。每个镜头必须给出情绪的前后变化：

| 项 | 要求 |
| --- | --- |
| 起点情绪 | 镜头开始时人物处于什么情绪，承接上一镜头 |
| 触发事件 | 由哪句台词、哪个动作或哪条信息引发变化 |
| 转折位置 | 变化发生在镜头的第几秒，用于决定反应镜头的切点 |
| 终点情绪 | 镜头结束时停留在哪种情绪，作为下一镜头的起点 |
| 外化表现 | 表情、呼吸、视线、手部与身体紧张度的具体表现，不写抽象形容词 |

写入 `shot.emotion_curve`。`shot.emotion` 保留为配音取用的主情绪标签，取值固定为 neutral / happy / sad / angry / fearful，取该镜头终点情绪。整镜情绪无变化时仍须填起点与终点（可相同），并说明无需变化的原因。

### 4.6 单集节奏与结尾悬念（P0）

自动拆分剧情时不得按固定字数或固定镜头数截断，必须保住叙事节拍：

| 节拍 | 位置要求 | 作用 |
| --- | --- | --- |
| 开场钩子 | 本集前 5 秒内 | 给出异常、冲突或强信息，阻止划走 |
| 冲突升级 | 本集中段 | 阻碍加码，主角目标受挫 |
| 情绪释放 | 升级之后 | 给一次明确的爽点、虐点或甜点兑现 |
| 结尾悬念 | 本集最后 5 秒内 | 留下未解问题，驱动看下一集 |

集级信息随解析结果一并输出为 `episodes` 数组，每项含 `episode`（集数）、`goal`（本集目标）、`rhythm_curve`（节奏曲线，标注钩子、升级、释放、悬念各自的时间点）、`cliffhanger_type`（悬念类型：信息缺失 / 危机逼近 / 反转揭示 / 关系破裂）、`hook_to_next`（下一集承接点）、`locked`（是否锁定，默认 false）。该数组按集写入 `project.episode_plan`。

按集覆盖规则：

| 情形 | 处理 |
| --- | --- |
| 该集未锁定 | 用新解析结果覆盖该集规划 |
| 该集已锁定 | 保留原规划，新解析结果丢弃，并在解析结果中标注为已跳过 |
| 新解析出现原规划没有的集 | 直接新增该集，locked 默认 false |
| 原规划有而新解析没有的集 | 未锁定时删除，已锁定时保留并标注为孤立集，提示人工确认 |

交互要求：
- 发起解析前，若存在已锁定集，确认弹窗列出这些集并提示本次不会覆盖
- 解析结果确认界面按集展示变更前后差异，已锁定集显示为只读
- 锁定与解锁在分集规划界面单集操作，锁定后该集规划字段不可编辑
- 集级锁定与资产锁定互不影响，前者只约束解析覆盖，后者约束资产删除与引用

### 4.7 输出必须可被后续模块消费（P0）

解析与分镜结果必须是可校验的结构化 JSON，不接受纯自然语言分析报告。硬性要求：

1. 角色、场景、道具、镜头一律使用稳定 ID，分别以 `chr_`、`scn_`、`prp_`、`sht_` 为前缀，跨集跨场景不重建
2. 每个镜头必须给出参考资产（对应 `asset_ref` 的资产 ID 与 role）、生成方式（T2VA / I2VA / Ref2VA）、时长、对白、音效、审核条件，缺任一项视为解析结果不合格
3. 生成方式按素材可得性判定：无任何参考素材取 T2VA，仅有分镜图取 I2VA，有角色/场景/道具参考取 Ref2VA
4. 审核条件写成可判定的短句，如「人物面部无畸变且服装与定妆图一致」，不写「画面好看」这类不可验证表述
5. 字段命名与 API.md 保持一致，不得自造同义字段

## 5. 结构化提示词模板

### 5.1 分镜图提示词模板（写入 shot.image_prompt）

分镜图采用固定分段的结构化提示词，替代自由文本描述。分段写法让模型明确知道哪些特征必须保持、哪些允许变化、哪些绝对禁止。

模板结构：

```
任务：{任务类型}

参考图 1：{槽位职责一}
参考图 2：{槽位职责二}
参考图 3：{槽位职责三}

目标画面：
{画面主体、动作、构图、景别、光线、质感}

必须保持：
{跨图一致性要求，逐项列出}

允许变化：
{明确允许模型自由发挥的部分}

禁止：
{必须避免的缺陷，逐项列出}

输出：{产物形态与质量要求}
```

分段填写规则：

| 分段 | 必填 | 填写要求 |
| --- | --- | --- |
| 任务 | 是 | 任务类型，如多参考图人物一致性生成 |
| 参考图职责 | 否 | 有对应槽位绑定时才写，逐行对应槽位编号与职责 |
| 目标画面 | 是 | 主体、动作、构图、景别、光线、质感，一段连续描述 |
| 必须保持 | 是 | 逐项列出，建议 3–6 项，聚焦身份与外观 |
| 允许变化 | 否 | 列出可自由发挥项，减少模型过度约束 |
| 禁止 | 是 | 逐项列出，覆盖人物畸形、换脸、无关元素、水印等 |
| 输出 | 是 | 产物形态与清晰度要求 |

结构化模板是推荐写法，不是强制格式。用户仍可直接写自由文本，系统不做格式校验。分镜图提示词存入 `shot.image_prompt`，视频用的 H3 提示词存入 `shot.video_prompt`，两类格式分列存储，互不污染。

### 5.2 视频提示词模板（写入 shot.video_prompt）

视频提示词按固定的状态衔接结构编写，显式声明本镜头的起始状态与结束状态。模板结构：

```
任务：{生成方式与镜头编号}

【参考图1：上一镜头尾帧】
本镜头开始时的连续状态基准。重点参考人物当前位置、站姿、身体朝向与面部表情，视线方向、手臂位置与动作状态，手中道具及位置，人物与场景中其他物体的空间关系，以及当前场景的光线、色调、背景与屏幕方向。

【参考图2：当前镜头分镜图】
本镜头结束时的目标视觉效果基准。重点参考景别、构图、机位与镜头角度，人物外貌、发型、服装与配饰，场景布局与人物之间的空间关系，以及本镜头需要表现的关键动作与情绪。

【身份约束】两张参考图中的同一人物必须保持面部特征、发型、服装、体型与配饰一致，不得无故更换外观。

开场状态（承接参考图1，六项取枚举值）：
人物位置：{...}
身体姿态：{...}
视线方向：{...}
道具状态：{...}
情绪状态：{...}
空间与机位：{...}

剧情与动作：
本镜头剧情：{该镜头实际发生的剧情事件}
人物动作：{按 beats 逐拍描述}
人物情绪：{由什么触发、如何随动作变化、最终停留在哪种情绪}
镜头运动：{固定/推/拉/摇/移/跟拍}
画面衔接：{开场保持参考图1 的位置、姿态、视线与道具状态，随动作自然过渡到参考图2 的构图与动作}

目标状态（对齐参考图2，六项取枚举值）：
人物位置：{...}
身体姿态：{...}
视线方向：{...}
道具状态：{...}
情绪状态：{...}
空间与机位：{...}

必须保持：
{跨镜一致性要求，逐项列出}

允许变化：
{明确允许模型自由发挥的部分}

禁止：
{必须避免的缺陷，逐项列出}

对白与声音：
{台词、环境声、动作音效、背景音乐}

输出：{时长、帧率、画幅与质量要求}
```

分段填写规则：

| 分段 | 必填 | 填写要求 |
| --- | --- | --- |
| 任务 | 是 | 生成方式（T2VA / I2VA / Ref2VA）与镜号，如 Ref2VA 第 12 镜 |
| 参考图职责 | 否 | 参考图1 为上一镜头尾帧，参考图2 为当前镜头分镜图，两者职责不同不可互相替代 |
| 开场状态 | 推荐 | 六项逐项取枚举值，与本镜头 `start_state` 字段同源，须与参考图1 可见状态一致 |
| 剧情与动作 | 是 | 剧情一句话；动作按 beats 逐拍写；情绪写触发与走向；运镜与 `camera_movement` 一致；衔接写从参考图1 到参考图2 的过渡 |
| 目标状态 | 推荐 | 六项逐项取枚举值，与本镜头 `end_state` 字段同源，须与参考图2 目标画面一致 |
| 必须保持 | 是 | 3–6 项，聚焦身份、服装、道具与空间关系 |
| 允许变化 | 否 | 列出可自由发挥项，避免过度约束导致动作僵硬 |
| 禁止 | 是 | 覆盖换脸、服装跳变、道具消失、多余肢体、文字水印等 |
| 对白与声音 | 是 | 台词与 `dialogue` 一致，声音设计对应 `soundscape` 与 `bgm` |
| 输出 | 是 | 时长按 `duration`，画幅按 `project.aspect_ratio` 对应的基准分辨率 |

本模板为推荐写法，不是强制格式：用户可直接写自由文本，系统不做格式校验，仅在生成前对缺失起始状态或衔接信息的镜头给出 warning 级提示（检查项见 WORKFLOW.md 第 10.3 节骨架完整性检查）。

## 6. 资产图提示词模板规范（P4 整改）

资产图（角色定妆图/场景基准图/道具锚定图）与分镜图是两类不同任务：资产图定义固定视觉身份，单一主体、干净背景、不讲述剧情；分镜图允许按剧情组合多个角色、场景与道具。资产图的单主体约束不得应用到分镜图。

### 6.1 模板实现与版本

- 实现位置：`backend/app/services/asset_prompts.py`，模板版本常量 `ASSET_PROMPTS_VERSION`（当前 2.0）。
- 外置机制（P1）：静态模板文本外置为 `workspace/prompts/asset_*.md`（可 UI 编辑），动态变量 `{name}/{identity}/{style}` 由代码运行时 `str.format()` 注入。外置文件缺失时回退到模块内 `DEFAULT_PROMPTS` 兜底模板（零配置可用）。3 个构造器 `build_character_prompt` / `build_scene_prompt` / `build_prop_prompt` 已统一为 `get_prompt(name)` + `.format()` 模式，静态文本不再是代码的一部分。必填校验（`_require_identity`）、负面约束（`negative_for_asset_type`）、默认风格（`_DEFAULT_STYLE`）与版本标记保留在代码内，不进入外置模板。
- 版本追溯：生成任务创建时版本写入 `job.params.__asset_prompt_version__`；executor 执行时剥离该标记并持久化到 `job.input_snapshot.asset_prompt_version`，不作为参数提交给工作流。
- 必填校验：名称/外观/描述全部为空时构建函数抛 `ValueError`（`*_prompt_missing_identity`），API 层返回 422，不静默生成占位提示词；仅有名称时名称作为身份兜底，不虚构外观。

### 6.2 负面约束注入规则

- 负面约束按资产类型区分（`negative_for_asset_type`：character/scene/prop 三套独立文本）。
- 注入条件：工作流定义中实际绑定了 `$negative.*` 参数标记（由 `parse_workflow` 解析）时才注入 `params.negative`；未绑定时不注入，避免写入无人消费的参数。
- 历史问题：此前依赖 `capabilities.negative_prompt` 声明，但现有工作流均未声明该字段，导致负面约束从未实际生效（P4 已修复）。

### 6.3 未注入参考图槽位剔除

- 工作流定义中的 LoadImage 参考图节点带有占位图（`placeholder_*.png`）。未注入槽位时占位图连线原样提交会污染生成结果（资产图混入陌生主体的根因之一）。
- executor 在注入参数前调用 `prune_unbound_media_inputs`：剔除未提供媒体的参考图节点及所有消费连线，并写 `job.media_pruned` 事件记录被剔除槽位。
- 必填媒体参数（标记带 `!`）缺失时不剔除，仍由 `inject_params` 报必填参数缺失错误，不静默丢失必需参考图。

### 6.4 数据隔离规则

- 角色模板只读取当前角色的名称/外观/简介；场景模板只读取当前场景的标题/描述；道具模板只读取当前道具的名称/外观/简介。
- 分镜提示词（`shot.image_prompt`）由剧本解析按 §5.1 模板生成，出场角色/场景未显式 @引用 时由 `inject_asset_refs` 自动补入（仅注入有正式资产图的实体）。
- 视频提示词（`shot.video_prompt`）按 §5.2 状态衔接模板生成，executor 自动注入当前分镜图（ref_image）、上一镜尾帧（ref_prev_frame）与跨集首帧（first_frame）。

### 6.5 video_prompt 兜底模板外置（P1）

当 LLM 未生成 `video_prompt` 时，`_assemble_video_prompt()` 从外置模板拼装兜底提示词（首镜/非首镜各一版）。静态文本已外置为 `workspace/prompts/video_prompt_{first,body}.md`，变量 `{episode}/{seq}/{beats}/{shot_purpose}/{camera_movement}/{start_state}/{end_state}/{sound}/{duration}` 由代码运行时注入。文件缺失时回退到模块内 `DEFAULT_PROMPTS`。
