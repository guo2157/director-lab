# 03. 提示词冲突矩阵

审计日期：2026-11-25
审计对象：27 个运行时注册模板的全部两两组合
判定方法：difflib.SequenceMatcher 文本相似度 + unified diff 逐行比对 + 代码常量引用链核对
数据来源：运行时直读，非人工估计

---

## 一、判定口径

模板之间的矛盾分为四类，只有第四类才是真正需要处置的『冲突』：

| 类别 | 定义 | 是否处置 |
| --- | --- | --- |
| 必要分叉 | 同一领域内因业务阶段不同而必须存在差异的条款 | 不合并 |
| 结构重复 | 多模板共享同一段通用条款，存在多处维护成本 | 可抽取公共段 |
| 语义重叠 | 不同模板对同一概念使用不同措辞但含义一致 | 记录，不强制统一 |
| 真实冲突 | 两个模板对同一事实给出互斥指令，且可能同时作用于同一产物 | 必须修复 |

## 三、逐对差异分析

### 3.1 video_prompt_first 与 video_prompt_body（0.769）

结论：必要分叉，不合并。

差异逐行核对（unified diff 全文已核对），全部集中在 H3 首镜与续镜的参考图职责：

| 维度 | video_prompt_first | video_prompt_body |
| --- | --- | --- |
| Picture 1 | 当前镜头分镜图，承担构图/身份基准 | 上一镜头尾帧，仅提供时间空间连续性 |
| Picture 2 | 不存在 | 当前镜头分镜图，承担构图/身份基准 |
| 身份约束 | 参考图中的同一人物保持一致 | 两张参考图中的同一人物保持一致 |
| 开场状态 | 按剧情与分镜图推断 | 承接上一镜头尾帧 Picture 1 |
| 画面衔接 | 按剧情自然进入当前镜头构图与动作 | 从第一帧起完整属于当前镜头，Picture 1 仅提供连续性 |
| 目标状态 | 对齐当前镜头分镜图 | 对齐 Picture 2 |

这正是项目硬约束所要求的 H3 规则：首镜由当前分镜图承担构图与身份基准；后续镜 Picture 1 为上一镜尾帧（仅连续性，不得替换人物身份）、Picture 2 为当前分镜图。若强行合并为单模板，会导致首镜出现 Piture 2 的空槽或续镜丢失连续性注入，破坏生成链路。

维护风险与对策：两份模板的 Picture 段落天然需要同步演进。建议后续为『身份约束』『开场状态』等公共段建立一致性测试（类似 76a2770 的内外置防漂移思路），而非合并模板。

### 3.2 script_create_system 与 script_expand_system（0.616）

结论：结构重复，可抽取公共段，但本轮不改。

差异逐行核对：

| 维度 | script_create_system | script_expand_system |
| --- | --- | --- |
| 首句职责 | 根据创意或故事设定创作完整剧本 | 将故事梗概扩写为完整剧本 |
| 忠实性要求 | 无 | 保留核心事件、人物关系、结局走向，不改变主线 |
| 补全要求 | 无 | 补全场次、动作细节、对白与情绪层次 |
| 剧本格式 | 场次标题、场景描述、人物动作、对白、旁白与声音提示 | 同 |
| 集分隔 | 每集以第X集分隔，集内场次连续编号 | 每集以第X集分隔 |
| 一致性 | 人物名全剧一致、同一地点统一场景名 | 人物名与场景名全剧一致稳定 |
| 节拍要求 | 开场吸引点、冲突升级、情绪高潮、结尾承接四节拍 | 无 |
| 结尾句 | 只输出剧本正文，不输出创作说明或分析 | 只输出剧本正文，不输出扩写说明 |

重复项为：剧本格式条款、第X集分隔、人物与场景名一致、只输出正文。这 4 条与职责无关，属于通用输出规范。

为何本轮不改：抽公共段意味着两处模板文本实际变更，会改变模型输入，进而影响剧本生成结果。按项目硬约束『不把推测写成已验证事实』与『重要模板修改前保留原版本』，必须先建立 A/B 基线再动。列入 05 计划。

## 四、负向词单一事实源核验

项目自 P1-2（72fc8c2）起将负向词收编为单一事实源，本次核验代码引用链如下（逐行直读确认）：

| 层级 | 常量 / 字典 | 位置 | 内容性质 |
| --- | --- | --- | --- |
| 通用层 | COMMON_NEGATIVE | prompt_compiler.py:64 | 画质、结构、文字、水印等跨类型通用负向词 |
| 类型层 | CHARACTER_NEGATIVE / SCENE_NEGATIVE / PROP_NEGATIVE / STORYBOARD_NEGATIVE / VIDEO_NEGATIVE | 第 72 行起定义 | 按资产与任务类型区分 |
| 类型字典 | _NEGATIVE_BY_TYPE | 第 108 行 | 5 个键全部直接引用上述常量，无字面量双写 |
| 历史层 | _LEGACY_CHARACTER_NEGATIVE 等 | 第 130 行起 | 原 asset_prompts 内联定义，P1-2 收编 |
| 历史字典 | _LEGACY_NEGATIVE | 第 130 行所在区块 | 3 个键（character / scene / prop） |

合并入口唯一：

```python
def negative_for(asset_or_task_type: str) -> str:
    specific = _NEGATIVE_BY_TYPE.get(asset_or_task_type, "")
    legacy = _LEGACY_NEGATIVE.get(asset_or_task_type, "")
    return merge_negative(COMMON_NEGATIVE, specific, legacy)
```

关键结论：

1. 全库不存在第二处独立维护的负向词列表，asset_prompts 的负向词已委托 negative_for，P1-2 目标达成。
2. _NEGATIVE_BY_TYPE 引用常量而非复制字面量，修改常量即全链路生效，无同步风险。
3. 三层之间按分隔符切分后去重（merge_negative），因此历史层与类型层出现重复词（如『身体结构错误』同时存在于 CHARACTER_NEGATIVE 与 _LEGACY_CHARACTER_NEGATIVE）不会造成重复下发，属可接受的冗余。

历史层与类型层的重复词抽样（实读）：

| 词 | 类型层 | 历史层 |
| --- | --- | --- |
| 身体结构错误 | CHARACTER_NEGATIVE | _LEGACY_CHARACTER_NEGATIVE |
| 手持无关道具 | CHARACTER_NEGATIVE | _LEGACY_CHARACTER_NEGATIVE |
| 人物剪影 | SCENE_NEGATIVE | _LEGACY_SCENE_NEGATIVE |
| 人物 | SCENE_NEGATIVE | _LEGACY_SCENE_NEGATIVE |

这些重复不构成冲突（去重后只下发一次），但历史层已无独立信息增益，未来可在确认无回归后清理。本轮保留，理由同 3.2：删除会改变下发的负向词集合，需要 A/B。

其余模板最多命中 2 项。含义：身份、站位、道具、参考图职责这四类高风险约束只集中在 video_prompt_first / body 两个模板里表达，其余模板不做重复约束，不存在『A 模板说必须、B 模板说禁止』的互斥风险。

同时验证了『禁止用固定字数判断合格』硬约束：

| 模板 | 字数类表述 | 是否违反约束 |

## 七、结论

1. 全库不存在互斥指令型冲突，27 个模板之间没有『同一产物被两条相反规则约束』的情况。
2. 唯一需要后续治理的是 C-02 的结构重复（4 条通用剧本格式条款），属维护成本问题而非功能缺陷。
3. 负向词单一事实源经代码引用链核验成立：5 个类型键全部引用常量，合并入口唯一为 negative_for，去重由 merge_negative 承担。
4. C-01 的两份视频模板需要在未来同步演进，建议以测试守护替代合并，与 76a2770 的防漂移思路一致。
