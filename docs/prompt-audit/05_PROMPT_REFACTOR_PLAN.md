## 三、待办任务清单

### P3-1 剧本创作模板公共段抽取（对应 02 的 Q-01、03 的 C-02）

问题：script_create_system 与 script_expand_system 共享 4 条通用输出规范（剧本格式、第X集分隔、人物与场景名一致、只输出正文），相似度 0.616，存在双处维护成本。

方案：

1. 抽取公共段为独立模板片段（例如 script_common_format），两模板在渲染时拼接。
2. 或保持两模板独立，但新增一致性测试，断言「4 条通用规范在两者中同时存在或同时缺失」。

推荐：先做方案 2（零风险，不改模型输入），观测一轮后再评估方案 1。

风险：方案 1 会改变模型实际收到的文本顺序与边界，可能影响剧本生成风格。

验证：方案 2 由 pytest 断言即可；方案 1 需 A/B 对比剧本格式合规率与人工抽检。

回滚：方案 1 回滚方式为 Git revert 加 .bak 恢复；方案 2 无回滚需求。

优先级：中。前置条件：06 文档 A/B 基线建立完成。

状态：方案 2 已完成（2026-11-25，提交 a95ee66）。新增 tests/test_script_prompt_common.py 6 项，守护 4 条实测共享规范、人物名一致性（两份措辞不同，分别断言不强行统一）、职责边界、专属规则不互相串入；含 3 项模拟漂移反向验证。方案 1（抽公共段）代码修改已完成（2026-11-26，提交 b50acd1）：新增 _SCRIPT_COMMON_FORMAT / _SCRIPT_COMMON_EPISODE / _SCRIPT_COMMON_CONSTRAINTS / _SCRIPT_COMMON_OUTPUT 四个共享常量，两个模板改为括号拼接引用；get_prompt 返回值与原版逐字符一致（create 296 字符、expand 266 字符），test_script_writing / test_script_prompt_common 共 11 项通过。

模型输入等价性已由工具直读闭环（2026-11-26）：prompt_store.get_prompt（prompt_store.py:80-90）外置文件优先、缺失回退 DEFAULT_PROMPTS；PROMPT_DIR 指向 backend/workspace/prompts，实测该目录存在但 script_create_system.md 与 script_expand_system.md 均不存在，故两模板实际取值均为内置默认值；两个消费点 script_writing.py:331 与 video_workflow.py:274 均把 get_prompt 返回值直接赋给 system 变量；LLMClient.chat（llm.py:213-223）原样构造 role=system、content=system_prompt 的消息并交给 chat_messages，后者直接置入 payload 的 messages 字段，全链路无 strip、无拼接、无截断。因此重构前后模型收到的 system 内容字节级相同，本次改动不改变模型输入，A/B 在输入侧不适用；输出侧非确定性源于 temperature=0.3，与本次改动无因果关系。

### P3-2 历史负向词层清理（对应 03 的 C-03）

问题：_LEGACY_NEGATIVE 三个键（character / scene / prop）与类型层存在重复词，例如「身体结构错误」「手持无关道具」「人物剪影」同时出现在两层。merge_negative 去重后不重复下发，历史层已无独立信息增益。

方案：

1. 逐词比对历史层与类型层，产出差集（仅在历史层出现的词）。
2. 若差集为空则整层删除；若非空则把差集并入类型层后删除历史层。

风险：删除会改变实际下发的负向词集合，可能影响出图画质分布。

验证：删除前后对比 negative_for 五种类型的输出字符串，确认最终集合等价；再跑 A/B 出图抽检。

回滚：Git revert 单项提交即可完整恢复。

优先级：低。前置条件：差集分析完成且出图抽检通过。

状态：差集分析已完成，原方案被实证证伪，改用了零影响方案（2026-11-25，提交 c119c45）。

实证结论（三项，均为运行时直读）：

1. 历史层并非重复层：含 23 个类型层与通用层都没有的独有词（character 11 / scene 7 / prop 5），整层删除会丢失信息。原方案前提「历史层已无独立信息增益」不成立。
2. 「把独有词并入类型层再删历史层」会改变下发词序：虽然去重后词集合等价，但五种类型中 character / scene / prop 三类 negative_for 输出字符串不一致（长度相同、顺序不同），会改变模型实际输入。
3. 真正零影响的精简是只删除「已被类型层覆盖、经 merge_negative 去重后永不下发」的 6 个重复词（character 的 身体结构错误 / 手持无关道具，scene 的 人物 / 动物 / 人物剪影，prop 的 人物）。已执行并验证：五种类型输出长度 422 / 337 / 337 / 364 / 311 与修改前逐字符一致，79 项相关测试全部通过。

仍未做：整层删除或合并进类型层，因会改变模型输入，须 A/B 出图抽检，按 H-8 暂缓。代码中已加注释记录上述结论，防止后续误删。

### P3-3 单行超长模板格式化（对应 02 的 Q-03）

问题：director_system（1 行 940 字符）、voice_profile_system（1 行 482 字符）、session_title_system（1 行 23 字符）为单行文本，diff 审阅与协作不友好。

方案：按语义分段换行，不增删任何文字内容。

风险：换行符本身是模型输入的一部分，可能影响输出。虽然语义不变，但经验上对长文本模型存在扰动可能，必须实测。

验证：对同一批输入，格式化前后各跑一次，对比输出结构与关键字段；确认无变化后再合并。

回滚：.bak 与 Git revert 双保险。

优先级：低。前置条件：上述 A/B 基线。

状态：预备分析已完成（2026-11-25，提交 6d320a9）。

分析结论：

1. director_system（940 字符 1 行）按语义拆为「导航段 / 角色说明段 / 联网搜索规则 / 任务状态纪律」四块 21 行，去换行后与原版逐字符一致（flat_diff=+0）。
2. voice_profile_system（482 字符 1 行）拆为「角色说明 / JSON 格式 / 规则」三块 6 行，同样逐字符一致。
3. session_title_system 仅 23 字符，无分段必要。

两个分段方案的精确文本已保存至 docs/prompt-audit/reference/p33_*_segmented.txt，各含 UUID 锚点供 A/B 比对时引用。

代码修改已完成（2026-11-25，提交 d644bc6）：agent.py 的 _DIRECTOR_SYSTEM_PROMPT（940 字符 1 行 → 22 行）与 voice_matching.py 的 _VOICE_PROFILE_SYSTEM（482 字符 1 行 → 6 行）已按 reference 目录分段方案完成语义换行。验证：get_prompt 返回文本去换行后与修改前逐字符一致（flat_diff=+0），133 项提示词专项测试全部通过（17.05s）。

仍未做：分段换行增加了 20+ 个换行符，这些字符会进入模型的 token 序列，按 H-8 必须在 A/B 基线就绪后执行，不能只凭字符级等价就声称无影响。
