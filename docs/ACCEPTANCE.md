# ACCEPTANCE —— 验收标准与测试用例

> 本文档是验收与测试的唯一权威定义（P0）。每条需求验收前先读本文档；功能完成后必须对照对应 TC 用例自测（见 AGENTS.md 第 4 节）。失败分类的界面分派见 ARCHITECTURE.md 5.5 节，接口字段见 API.md。

## 1. 验收标准

### 1.1 功能级

1. 主流程可在单个项目内完整跑通，全程无需手工改库；合成完成与最终导出完成分别验收
2. 每条 P0 需求有可执行的验收步骤与明确预期
3. 所有失败场景返回约定错误码（API.md 第 2 节），前端按 ARCHITECTURE.md 5.5 节分派重试按钮或修改指引
4. 阶段完成判定（D-21 流转链，2026-10-25）：
   - 解析阶段完成：所选集全部集级解析记录 succeeded，摘要卡片展示场景/角色/道具数量，出口按钮『去资产库』可跳转
   - 资产库阶段完成：角色 portrait_asset_id、场景 baseline_asset_id、道具 anchor_asset_id 全部非空（齐全度 N/M 显示 M/M），『去分镜看板』按钮解禁
   - 分镜阶段完成：已解析集全部镜头具备分镜图（keyframe）与视频片段（clip）产物，就绪度横幅显示完成，『去合成导出』按钮解禁
   - 门槛校验：公共资产未齐全时分镜看板顶部显示引导横幅；分镜未就绪时合成入口禁用；禁止跨级跳转按钮出现

### 1.2 质量级

| 项 | 标准 |
| --- | --- |
| SSE 断线恢复 | 断网 5 分钟后恢复，3 秒内自动重连并补齐状态，界面 2 秒内收敛 |
| 任务恢复 | 重启后图像与视频任务均按已写入的远端任务 ID 继续轮询；仅在远端任务 ID 缺失且无法补查时标记 lost，并保留提交时间戳可查原因 |
| 合成精度 | 成片时间轴与逐镜实际有效对白/旁白音频时长（`actual_duration`）累加值误差不超过 100 毫秒 |
| H3 VA 音视频校验 | 每个对白/旁白镜头均记录视频时长、音轨存在性、音频时长、对白检查结果及音画差值；缺音频或检查失败时触发可追踪的 TTS 补救/人工审核 |
| H3 时长规划 | 生成任务提交前校验目标时长、帧率、帧数步长与工作流能力；无法合法对齐时阻断提交并给出调整建议 |
| 备份可用 | 备份包可在干净环境完整恢复并通过全部校验 |

| TC-11 | 失败重试 | 构造 comfy_upload_failed 失败任务 | retryable 为 true，界面展示重试按钮；重试生成新 job id，旧 job 保留；累计重试达 job_max_attempts 后 retryable 转 false（见 ARCHITECTURE.md 5.7 节） |
| TC-12 | 重启续跑与提交对账 | 图像/视频任务运行中重启 worker；另模拟远端已接收但本地未保存远端 ID | 有远端 ID 的继续轮询；未知提交状态先对账并标记 submission_unknown，不得无条件重复提交；确认远端不存在后才可重试 |
| TC-13 | 合成时间轴 | 三镜头有效音频 `actual_duration` 为 2.3、1.7、3.1 秒，来源可混合 H3 VA/TTS 补救 | 起始时间为 0、2.3、4.0，总长 7.1 秒，误差不超过 100 毫秒；每镜来源与检查状态可追溯 |
| TC-14 | 音画不等长 | H3 VA 视频 3.0 秒、内嵌音频 3.4 秒 | 差值 0.4 秒在容差内，末帧定格补齐至 3.4 秒；差值 1.0 秒时镜头进入 review，合成返回 422 `duration_mismatch_review_required`，人工放行或重生成后方可继续 |
| TC-15 | 字幕切分与边界 | 输入短镜头内多句台词，且无词级时间戳 | 允许按句级/文本长度估算；1 秒为软约束，字幕不重叠且不越过镜头边界，估算时间写入合成报告 |

| TC-17 | 分集合成 | 项目含两集，请求合成第 2 集 | 仅合成第 2 集镜头，按 seq 串联，时长等于该集累加值 |

| TC-19 | 角色改名同步 | 角色由小明改名为小刚，某镜头 image_prompt 含 @小明 | 该镜头 image_prompt 与 video_prompt 中的 @小明 同步改写为 @小刚 |
| TC-20 | 备份恢复 | 执行备份后在干净环境恢复 | integrity_check 通过，文件清单与校验和一致，项目详情可打开，产物可正常播放 |
| TC-21 | 重新解析保护 | 已人工编辑并生成部分镜头后重新解析 | 先生成候选版本与差异；未确认不改当前版本；确认后旧产物仍可追溯，旧任务标记取消/过期 |
| TC-22 | 工作流必需参数 | 工作流缺少任一 required_params 或类型不匹配 | 不进入候选列表；返回具体节点/字段错误，不以匹配数量放行 |

| TC-24 | 音轨时间线 | 一集含多人对白、SFX、BGM | 优先使用 H3 VA 同次生成的音轨并记录来源；只有音轨缺失/无效或对白审核失败才创建 TTS 补救任务；各轨道起止、音量与淡入淡出正确，BGM/SFX 缺省不阻塞 |
| TC-25 | 纯视觉镜头 | 生成无对白纯视觉镜头并合成 | 不创建 TTS 补救任务；视频必需产物校验通过，若 H3 返回环境音则可保留并记录来源，字幕不生成空条目 |
| TC-26 | 独立导出阶段 | 成功合成后调用 export | export 创建独立 job 和 export 记录；未合成、composition 过期时拒绝导出 |

| TC-28 | 可选道具锚定图 | 普通道具无 anchor_asset_id，且 anchor_required=false | 生成流程可继续并注入文字描述；anchor_required=true 且缺图时阻止依赖该图的生成 |
| TC-29 | 事件可靠性 | 在数据库提交前后模拟服务崩溃并重连 SSE | 事件可按 event_seq 补拉，重复事件幂等，最终状态与数据库一致 |
| TC-30 | 媒体标记解析 | 上传含 `$ref_identity.~image`、`$prompt.value!`、`$output.clip` 的工作流；另传含 `$~ref_identity` 或指向连线字段的标记 | 前者解析出 ref_identity（media）、prompt（必填）、clip 输出；后者返回节点 ID 与字段名定位的错误 |
| TC-31 | 槽位剔除与编号 | 视频工作流仅注入 ref_image 与 ref_identity | 其余 LoadImage 节点与 `ref_images.ref_image_N` 连线被剔除，提交 JSON 通过 ComfyUI 校验；提示词中 `<Picture N>` 按剩余顺序重编号，`@名称` 不出现在提交内容中 |
| TC-32 | H3 时长边界 | `shot.duration` 分别为 3、5、16 | 3 与 16 返回 422 `h3_duration_unrepresentable`；5 写入 `$duration=5`，实际时长以探测为准并记录 |
| TC-33 | 参考图合规 | 参考图短边小于 256 像素，或宽高比超出 0.4–2.5；或无任何参考图 | 提交前返回 422 `h3_reference_required`，不创建 H3 任务 |
| TC-34 | sidecar 元数据 | 上传工作流并附 `*.meta.json`，另测将 capabilities 写入 JSON 顶层 | 前者 trigger 与 capabilities 正确入库；后者因顶层非节点映射被 `workflow_format_invalid` 拒绝 |
| TC-35 | Partner Node 未登录 | ComfyUI 未登录或额度不足时提交 H3 任务 | 任务失败为 `comfy_partner_auth_failed`，归为配置类，界面展示登录/充值指引，不自动重试 |
| TC-36 | 画幅改写 | 项目 `aspect_ratio` 分别为 9:16、16:9、1:1 | H3 任务 `model.ratio` 依次为 9:16、16:9、1:1；出图任务宽高分别为 720×1280、1280×720、1024×1024 |
| TC-37 | 视频工作流选择 | 依次请求：无任何参考；仅 first_frame；含 ref_image 与 ref_identity | 分别匹配 T2V、FLF2V、R2V；`first_frame` 路径下未传 `end_frame` 时剔除 last_frame 连线与节点，任务仍通过校验 |
| TC-38 | FLF2V 约束 | 首帧短边 200 像素或宽高比 3.0；首帧与尾帧比例不同 | 提交前返回 422 `h3_reference_required`；比例不同给 warning，画幅跟随首帧，不改写 ratio |
| TC-39 | TTS/BGM 路径 | 预设与克隆两种 `voice_id`；传 `tts_speed=1.5`；请求 `target=bgm` | 预设注入 `tts_voice`，克隆上传参考音频注入 `tts_voice_ref`；`tts_speed` 被忽略并记 warning；产物为 mp3，探测时长写入 `actual_duration`；bgm 解析到对应 `workflow_type`，输出为 `$output.bgm`。注：sfx 工作流本期不交付，SFX 相关用例暂缓执行（见 WORKFLOW.md 第 13 节） |

## 3. 上线前冒烟清单

按顺序执行，全部通过方可交付：

1. 新建项目，输入短剧本，解析成功并生成分镜结构；确认 `shot_kind`、`time_jump`、`requires_prev_frame` 已归一化
2. 生成一张角色定妆图并锁定
3. 生成一个镜头的分镜图，查看一致性评分与结论；关键道具锚定图未启用时不应阻塞
4. 生成一个 H3 VA 镜头，确认可播放且为 h264-mp4，记录实际视频时长、音轨存在性与音频时长；验证 `duration` 已取整并落在 4–15 秒（API 型工作流）或已按帧数规则对齐（帧数型工作流），并将探测到的 fps 回填至 job 的 `input_snapshot`（不修改工作流不可变版本）
5. 检查对白镜头音频与对白内容；正常时不创建 TTS 任务，缺失/无效/审核失败时才触发 TTS 补救，并确认 `actual_duration` 与音频来源已回写；多人对白补救时按正确 `speaker_id` 处理
6. 测试一条超容差镜头，确认镜头进入 `review` 且合成被阻止；审核放行或重生成后再继续
7. 执行合成，确认生成可预览 composition，时间轴按当前有效 H3 VA 音频或 TTS 补救音频的实际时长累加
8. 调用独立 `POST /api/projects/{id}/export`，确认导出任务成功，导出记录关联当前 `composition_id` 且下载可用
9. 归档并取消归档，确认状态流转正常；打开任务中心，确认失败任务展示重试按钮
10. 导出一份备份并完成校验；同场景连续生成两个镜头视频，确认第二镜头在 `requires_prev_frame=true` 时自动带入上一镜头末帧并正常生成

## 4. 交付完成判定

以下五组条件全部满足方可判定本期交付完成，任一项不满足即为未完成，不允许以『后续补』方式跳过：

| 维度 | 完成条件 | 验证方式 |
| --- | --- | --- |
| 主流程 | 从新建项目连续走通至最终导出，中途无需手工改数据库或调用未登记接口；合成与导出状态可区分 | 按第 3 节冒烟清单顺序执行一遍 |
| 一致性 | 双阈值可配置，三个评分区间分别产出 passed / review / failed，阈值变更只重算结论不标记 redo | TC-06 与 TC-08 |
| 连续性 | 视频提示词模板可选用，末帧自动抽取并落为资产，批量生成严格串行且仅依赖前镜产物/末帧的后续镜头暂停，独立镜头继续 | TC-12 与冒烟清单第 10 步 |
| 数据安全 | 备份可在干净环境完整恢复，迁移脚本具备 downgrade，启动时校验版本不一致即拒绝启动 | TC-20 与 ARCHITECTURE.md 9.5 节 |
| 文档一致 | 接口清单、字段表与实现代码三者口径一致，枚举取值无交叉混用 | 逐章比对，重点核对四套枚举 |

判定说明：

- 冒烟清单覆盖主链路，测试用例覆盖边界，两者都通过不等于完成，还须满足上表五组条件
- 涉及一致性、连续性的条目必须在同一次回归中验证，避免单点通过但组合失效
- 未通过项需登记问题单并明确责任人与修复期限，不进入交付验收

## 5. MVP 范围与真实链路验证

首版验收聚焦单项目、单集、3–5 个镜头：剧本评估与确认、可编辑分镜、参考图注入、H3 VA 音视频生成与检查、对白音频按需 TTS 补救、基础字幕、单条 BGM、FFmpeg 合成与 MP4 导出，以及失败重试、重启恢复和版本追溯。复杂跨集连续性、自动返工、智能调度优化和剪辑软件工程文件导出暂缓。

在宣称主链路可交付前，必须使用最终候选模型与工作流跑通 3–5 镜头，并记录成功率、平均耗时、显存峰值、重做率、参考图实际注入情况、音画同步问题和失败恢复结果。模型/工作流不支持的能力必须明确列为限制，不得以假设替代验证；本期已知限制与待实测项见 DECISIONS.md 第 3 节（T-01 至 T-08）。
