## 3. 实际流程链（代码实证）

用户消息 → POST /api/agent/sessions/{id}/chat → 用户消息持久化（agent_message）→ 项目上下文注入（execute_tool: project_overview + asset_stats + list_jobs，全部只读）→ 历史窗口（最近 40 条 user/assistant）→ LLMClient.chat_messages（会话 model 覆盖默认）→ 助手回复持久化 → 返回双消息。生成类操作不在 Agent 直接执行范围内（需通过对应页面/API），符合『模型负责推理、业务代码负责确定性控制』约束。

## 5. 缺陷记录

### CTX-001 [P2] [已修复] 项目上下文注入缺少任务列表

- 现象：询问『最近失败任务』时助手回复『无法确认』（上下文只有阶段与资产统计）
- 根因：agent.py 上下文注入仅执行 project_overview + asset_stats，未执行已注册的 list_jobs 工具
- 修复：注入最近 5 条任务摘要（类型/状态/错误码）到系统提示词
- 复测：助手准确列出 5 条失败任务（4×generate_keyframe comfy_unreachable + 1×generate_clip comfy_timeout），与数据库一致，并主动更正上轮回复
- 回归：pytest 118 passed
